# Ручной выбор сети проверок

Реализовано для текущего Mac + Colima: **Телефон** и **LTE-сеть**.
Панель не включает Personal Hotspot на телефоне и не управляет модемом/SIM/APN.
Remnawave не участвует в переключении; его конфигурация не изменяется.

## Использование после установки обновления

1. Один раз запустить обновлённый `./start.sh`. Он собирает новую версию и обновляет
   существующий launchd supervisor. Самостоятельный `docker compose up` не создаёт
   новый корректный сеанс bridge; основной вход — `start.sh`.
   Если активный профиль телефона не подключён, запуск использует сохранённый и
   подключённый LTE-профиль. Поэтому после однократной настройки LTE мониторинг
   запускается без подключённого телефона. Если ни один сохранённый адаптер не
   подключён, `start.sh` завершится с сообщением об отсутствующем интерфейсе, а не
   отправит измерения через случайный маршрут.
2. Открыть **«Сеть проверок»**. У каждого источника выбрать физический адаптер Mac.
   Список публикует host-supervisor; это не интерфейсы контейнера.
3. **«Сохранить адаптер»** запоминает неактивный профиль, не меняя текущий маршрут.
4. **«Проверить адаптер»** проверяет его наличие и IPv4. Это preflight, не доказательство
   работоспособности ещё не подключённого bridge или мобильного WAN.
5. После сохранения подключённого адаптера можно переключать источник прямо
   сегментной кнопкой в заголовке панели: **«Телефон» / «LTE-сеть»**. Переключение
   ставит типизированное задание supervisor. Раздел **«Сеть проверок»** оставлен
   для выбора и проверки физических адаптеров.
   Проверки закрываются gate, Colima останавливается и запускается с выбранным bridge.
   Панель временно пропадает, затем опрашивает сохранённый статус задания.
6. Источник становится активным только после проверки guest route, внешнего контроля
   и запуска checker. При ошибке выполняется попытка возврата прежнего bridge.
   Если прежний источник тоже отключён, статус явно сообщает неудачу отката;
   измерения остаются на паузе. Автоматического failover во время работы нет;
   выбор сохранённого альтернативного профиля применяется только при старте процесса.

Не переименовывается профиль Colima `iphone`: это техническое имя Docker daemon,
а не обещание использовать телефон. Named volumes и текущий порт панели сохраняются.
Старые глобальные snapshots не удаляются. Полная смена оформления панели из макетов
не является частью этого обновления: сохранены существующие карточки и Telegram-настройки.
Добавлен явный обзор подписок и фильтрация рабочей области по панели.

## Физическая сеть

Предпочтителен выделенный Ethernet/USB–Ethernet к LTE-only сегменту роутера.
Если роутер сам переключит этот сегмент на проводной WAN, панель этого не удостоверит:
интеграции с WAN API конкретного роутера пока нет. Отдельный SSID/внешний IP сами
по себе не доказывают мобильный WAN. Один адаптер Wi-Fi не обещает одновременное
подключение к домашнему SSID и отдельному LTE SSID.

Измерительные сокеты Go/Xray остаются привязаны к guest `col0`. Start использует
`--network-preferred-route`, явный DNS (по умолчанию `1.1.1.1`, override
`NETWORK_DNS_SERVER`) и IPv4 контрольные GET с отключённым proxy из окружения.
Физический адаптер выбирается как `enN`, а не подставляется вместо `col0` в Xray.
Это не отдельный network namespace для DNS/служебного трафика; control-plane VM
может пользоваться тем же мобильным маршрутом. Поддержка LTE/5G, IPv6 и независимой
доставки Telegram зависит от топологии, это не определяется одной зелёной TCP-пробой.

## Локальный протокол

Приватный каталог `.runtime/control/network-sources` имеет права `0700`, JSON — `0600`.
Сопоставление UID macOS/Colima проверено отдельно перед реализацией. Python использует
stdlib, file lock и атомарную замену snapshot; запрос публикуется Go атомарной ссылкой
на полностью записанный файл. При неподдерживаемых hard links запрос завершается
ошибкой, частичный JSON не выдаётся worker.

- `config.json`: активный source ID, epoch и адаптеры двух профилей.
- `status.json`: heartbeat, inventory, доступность сохранённых адаптеров и последнее job.
- `request.json` → `processing.json`: одна команда; произвольные команды/пути не принимаются.
- `network-source-control.py tick`: вызывается существующим supervisor до iPhone recovery.
  При активном роутере старая автоматика iPhone пропускается.
- Проверяются source/action/interface, текущая epoch, свежесть заявки и актуальный
  inventory. Preflight/configure не запускают VM. Полное применение и rollback
  вызывают только локальный `start.sh` с фиксированными аргументами и окружением.

API: `GET /api/v1/network/sources`, `POST /api/v1/network/sources`.
POST требует JSON, custom header `X-Xray-Action: network-source` и same-origin.
Тело: `action` (`configure|validate|activate`), `sourceId` (`iphone|router`),
`interface` (из inventory), `expectedEpoch` (из GET).
Возврат `202` означает **поставлено в очередь**, не «переключено».
Старый `/network/reconnect` отклоняет запрос при активном роутере или другой операции.
В публичном представлении управляющих элементов нет; API остаётся в защищённых routes.

## Измерения и история

При каждой пересборке bridge создаётся новая epoch, даже если public IP прежний.
Runtime source/epoch должны совпадать с heartbeat supervisor и sidecar.
Активная заявка на переключение, неверная/несвежая metadata или чужая epoch закрывают gate.
Управляемое определение source IP не использует старый кэш или обычный HTTP fallback.

Результаты, node history, диагностика, access-checks и эпизоды доставки Telegram находятся
в отдельных каталогах volume: `network-sources/<sourceId>/<epoch>/...`.
Старый процесс прекращается **до** смены bridge; его ответы не попадают в новый каталог.
Новый сеанс начинает с непроверенных привязок и ограниченных общей очередью запросов.
Перезапуск только контейнера с прежними source/epoch сохраняет возможность resume.

Telegram token/получатель/предпочтения остаются глобальными в прежнем settings file.
Недоставленная очередь старого сеанса не переносится в новый как свежий инцидент.
Это консервативная граница первой версии; отдельного UI просмотра архивных сеансов нет.
Для каждого источника сохраняются текущий и до пяти предыдущих каталогов сеансов;
старые legacy-файлы и настройки очистка не затрагивает.

## Проверка и установка

Тесты: `go test -race -count=1 -p 2 ./...`,
`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_network_source_control.py`,
`bash -n start.sh iphone-supervisor.sh`, `sh -n network-watch.sh`.
Host-тесты подменяют inventory/starter и команды Docker/Colima; проверяют успех,
ошибку, успешный/неуспешный rollback, исчезновение адаптера и устаревшую заявку.
Browser-проверка настоящего шаблона выполняется только с подставными API.

Разработка не перезапускает рабочую VM. Приёмка с реальным роутером выполняется отдельно:
выбранный адаптер/подсеть, работающий WAN, потеря кабеля при живом домашнем Wi-Fi,
потеря LTE при живом LAN, возврат на iPhone и отсутствие смешивания результатов.
Перед установкой сверить Python 3, Colima и поддержку bridged networking.

Технические основания: [Colima network flags](https://colima.run/docs/commands/#network-flags),
[Linux SO_BINDTODEVICE](https://man7.org/linux/man-pages/man7/socket.7.html),
[Python subprocess](https://docs.python.org/3/library/subprocess.html).
